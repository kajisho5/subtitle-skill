# ADR-004: Translation Engines — Offline Argos Translate by Default, DeepL Optional, Caller Translation Memory Built In

Status: Accepted

## Context

The owner kept the job 字幕翻訳 (subtitle translation) in this repository on 2026-10-30 (`ECOSYSTEM_ROADMAP.md`, "What this repository owns"). Step 4 asks for an engine choice, offline-capable, with the licences of its code and of its weights checked. Step 5 implements it, and step 6 muxes several languages into one video.

The main pair is Japanese ↔ English. Everything else this Skill does needs no network and no key (README: "no network access, no API keys"), and `security.py` refuses an `api_key` field anywhere in a request. A translation engine must fit that: the default has to run with no key, and CI must never download a model or call a paid API.

Every fact below was read from the page linked next to it on 2026-10-31. Where the page did not say, or could not be read, the table says **未確認 (unverified)**. Prices are list prices in the vendor's currency and change often; they are here to compare orders of magnitude, not to quote.

## Decision

1. **A provider abstraction, three engines.** `src/subtitle_skill/translation.py` defines a `TranslationEngine` interface: given the source and target language and a list of cue texts, return one text per cue, plus an `engine_version` for provenance. The request field `engine` picks one. Every engine sees the same input and its output goes through the same post-processing (points 4 and 5), so changing engines never changes how timing, line length or the glossary are handled.

   | `engine` | Needs | Network | When to use |
   |---|---|---|---|
   | `argos` (**default**) | `pip install argostranslate` and an installed language package for the pair | Never: refused unless Argos is set to its local (OpenNMT) provider | The offline default the roadmap asks for |
   | `deepl` | `DEEPL_AUTH_KEY` in the environment | Yes | Better quality, native glossary |
   | `memory` | Nothing | Never | A caller-supplied translation memory: exact source → target pairs (from a human, an earlier job, or an agent's own translation). Deterministic. Also what the tests and fixtures use |

2. **Argos Translate is the default and the offline engine.** It is the only candidate that is offline, has a permissive code licence, needs no PyTorch, and has packages for both ja→en and en→ja. NLLB-200's weights are non-commercial. OPUS-MT has no general en→ja model. The open question is the licence of the Argos weights: the index does not state it, so `doctor`/the README say so, and the user installs the package themselves (`argospm install translate-ja_en`, or `argostranslate.package.install_from_path`). **subtitle-skill never downloads a model.** It does not call `update_package_index`, `install_package_for_language_pair` or any other download API, and a missing package is a `DEPENDENCY_ERROR` naming the pair. Argos can also be configured to forward to LibreTranslate or OpenAI (`settings.model_provider`); the engine refuses anything but its local provider, so `argos` always means offline. Whether Argos's own sentence-boundary step fetches anything on first use is **未確認**; that step belongs to Argos, not to this Skill.
3. **DeepL is the optional external engine.** It has the most direct glossary support for JA↔EN (a real glossary resource, not a prompt). The key is read only from the environment (`DEEPL_AUTH_KEY`), never from a request (`api_key` stays forbidden). The base URL is `https://api-free.deepl.com` for a key ending in `:fx` (the convention DeepL's own client libraries use; not found stated in the API reference, so **未確認** there) and `https://api.deepl.com` otherwise; `SUBTITLE_SKILL_DEEPL_API_URL` overrides it. A glossary is created for the call and deleted afterwards. A target of `en` is sent as `EN-US` (and `en-GB` as `EN-GB`), because the spec only lists the regional English variants as examples of target codes; whether a bare `EN` target is accepted is **未確認**. Tests replace the HTTP layer; CI never calls DeepL.
4. **Not chosen.**
   - Google Cloud Translation: glossaries need the Advanced (v3) API, a Cloud project and service-account or OAuth credentials, against DeepL's single key. Its price is in the same range. It can be added later as one more engine behind the same interface.
   - LLMs: a prompt cannot guarantee a glossary term or a cue count, and an LLM paraphrases. That is the "semantic editing" this Skill lists as out of scope. An agent that wants an LLM translation can make it itself and pass the result as `memory`, so this Skill still enforces timing, layout and the glossary on it.
   - NLLB-200: non-commercial weights.
   - Marian/OPUS-MT directly: no general en→ja model, and running it needs PyTorch/transformers. (Argos already wraps OPUS-derived models in CTranslate2.)
5. **Timecodes are kept; layout constraints are applied again after translation.**
   - Each cue is translated as one segment: its lines are joined first (the same rule `locales._join_lines` uses), so the engine sees the sentence, not half of it.
   - `id`, `start`, `end`, `speaker`, `style` stay as they were. Timing is never stretched, merged or split, because the timeline belongs to the source and other tracks are muxed against it.
   - The translated text is re-broken for the **target** language: locale profiles (ja/zh/ko) with their full-width counting and kinsoku rules (`locales.break_lines`), other languages at spaces. Two lines are balanced (the break that makes the longer line shortest), never past `max_chars_per_line`.
   - The translated document is validated with the target language's profile and the request's `constraints`. Reading speed and anything else that still does not fit are reported as observations, as `generate` does. Rewriting the text to be shorter would be an editorial decision this Skill does not make.
6. **Glossary.** The request carries `glossary: [{"source": "...", "target": "..."}]`.
   - DeepL receives it as a native glossary.
   - Argos has none, so before translating each source term is replaced by its target term (longest first, exact match). Neural engines copy such a foreign term through in most cases.
   - After translation, every engine is checked the same way: a cue whose source contains a glossary term but whose translation lacks the target term gets a `GLOSSARY_TERM_MISSING` warning. The text is not patched.
7. **Provenance and reuse.** The sidecar and the translated document's `metadata.translation` record the engine, its version (Argos package and model package version; the DeepL API version; `memory` with the sha256 of the memory), the source and target languages and the glossary's sha256. All of these are part of the reuse identity, so a repeated request is served from the earlier output and is not translated or billed again. Only `memory` is deterministic. The reuse cache is what makes a repeated request return the same bytes for the other two.
8. **Contract.** Two operations are added: `translate` (step 5) and `mux` (step 6). This changes `operations`, `capabilities` and `parameters`, which video-production-agent pins (`FATAL_DRIFT_KEYS`). The agent has to re-pin from the release that contains them. The step 5/6 pull request says so. `contract_version` stays `1.0.0`: nothing an existing request or response carries changes.

## Consequences

- With nothing installed, `translate` works with `engine: "memory"` and fails cleanly (`DEPENDENCY_ERROR`, naming what to install) with `argos` or `deepl`. No key and no model are needed for CI or for the fixtures.
- The quality of the default engine on Japanese is not measured here. The Argos weight licence is **未確認**, so a commercial user should check the credits inside the package before shipping. Both points are in the README.
- Adding Google or another engine is a new class behind `TranslationEngine` plus a contract value, not a change to the pipeline.
- Known gaps: no sentence merging across cues (a sentence split over two cues is translated as two segments); glossary matching is exact (no inflection or case folding); `GLOSSARY_TERM_MISSING` is a check of the output, not a guarantee.

## Addendum (2026-10-31): the Argos ja→en weight licence, and two more optional engines

### What the package itself says

The open question in decision 2 was checked against the package, not the index. `translate-ja_en-1_1.argosmodel` was downloaded from the first link in [argospm-index `index.json`](https://github.com/argosopentech/argospm-index/blob/main/index.json) (`https://argos-net.com/v1/translate-ja_en-1_1.argosmodel`, 117,155,716 bytes, `Last-Modified: Sat, 31 Dec 2022`, sha256 `623e3477959a815eb0a5ef53e09079ae8f1f9d3bbcd230473baf28c03fb83335`), read, and deleted. It is a zip of 12 entries: `metadata.json`, `README.md`, `sentencepiece.model`, `model/model.bin` + `model/shared_vocabulary.txt` (the CTranslate2 model), and a Stanza Japanese tokenizer (`stanza/ja/tokenize/gsd.pt`, `stanza/resources.json`).

- `metadata.json` has exactly `package_version`, `argos_version`, `from_code`, `from_name`, `to_code`, `to_name`. **No licence field.**
- `README.md` (titled "English-Japanese") says "Data compiled by Opus", "Dictionary data from Wiktionary using Wiktextract" and "Includes pretrained models from Stanza", then lists as credits CCAligned (twice), WikiMatrix and OpenSubtitles2016. **It states no licence for the model.**
- No `LICENSE` file is in the archive. The Argos Translate README and the argos-train README give MIT / CC0 for their code only ("Argos Translate is dual licensed under either the MIT License or Creative Commons CC0"); neither says anything about the trained packages.

**Result: the licence of the Argos ja→en weights is not stated anywhere in the primary sources (index, package metadata, package README, code repositories). It stays unverified (未確認), not "non-commercial".** The credited corpora carry their own terms (for example WikiMatrix is derived from Wikipedia text, and the OpenSubtitles corpus is built from subtitle files whose owners never licensed them for this), which is why a commercial user cannot assume a permissive licence for the model either.

### OPUS-MT ja→en, checked the same way

- [`Helsinki-NLP/opus-mt-ja-en`](https://huggingface.co/Helsinki-NLP/opus-mt-ja-en): `license: apache-2.0` in the card's front matter and in the Hub API's `cardData` (model revision `0770961a39ba6bd66305b149c3f4110bcafca2e6`, last modified 2023-08-16). The card points at the original release `opus-2019-12-18.zip`, Tatoeba ja→en BLEU 41.7 / chr-F 0.589 (a short-sentence test set).
- The original release is described by [OPUS-MT-train's README](https://github.com/Helsinki-NLP/OPUS-MT-train#readme): models "are distributed with a CC-BY 4.0 license".

Both licences allow commercial use; CC-BY 4.0 asks for attribution (credit "OPUS-MT, Helsinki-NLP"). Either way OPUS-MT is the only offline ja→en model here whose weight licence is stated. For en→ja there is still no general OPUS-MT model (decision 4).

### Decision

9. **New optional engine `opus-mt`**: Helsinki-NLP OPUS-MT on CTranslate2 (MIT). The user converts the model once (`ct2-transformers-converter --model Helsinki-NLP/opus-mt-ja-en --output_dir <dir>/opus-mt-ja-en --copy_files source.spm target.spm`) and sets `SUBTITLE_SKILL_OPUS_MT_DIR=<dir>`. The engine imports `ctranslate2` and `sentencepiece` only when used, reads `<dir>/opus-mt-<src>-<tgt>/{model.bin,source.spm,target.spm}`, runs on CPU with beam size 4, and never downloads or converts anything (a missing package, directory or pair is a `DEPENDENCY_ERROR` saying so). `engine_version` is the CTranslate2 version plus the sha256 of those three files, so a different model is never served from the reuse cache. This also replaces the reason decision 4 gave against OPUS-MT ("needs PyTorch/transformers"): conversion needs them once, translation does not. Glossary terms are substituted into the source, as for Argos.
10. **New optional engine `ollama`**: a local LLM through [Ollama](https://github.com/ollama/ollama)'s HTTP API, `qwen3:8b` by default ([Qwen3](https://github.com/QwenLM/Qwen3): "All our open-weight models are licensed under Apache 2.0"). `SUBTITLE_SKILL_OLLAMA_URL` (default `http://127.0.0.1:11434`; plain `http://` only for a loopback host, so subtitle text never leaves the machine unencrypted) and `SUBTITLE_SKILL_OLLAMA_MODEL` choose the server and model; neither can be set from a request. This narrows decision 4's "LLMs: not chosen" for a local model only, because the two objections there are now handled mechanically: one `/api/chat` request per cue, so the cue count cannot drift; `temperature 0`, `seed 0` and `think: false`, with any `<think>` block stripped; glossary terms substituted into the source and checked afterwards like every engine. The remaining risk -- an LLM may paraphrase -- is accepted because the engine is opt-in and its output is validated exactly like any other engine's. subtitle-skill never calls `/api/pull`; a model that is not pulled is a `DEPENDENCY_ERROR`. `engine_version` is the Ollama server version plus the model's digest from `/api/tags`. Its JA→EN quality was not measured; compare it with Argos and DeepL on your own subtitles before relying on it.
11. **The default stays `argos`.** An omitted `engine` keeps meaning what it meant, because (a) the Argos licence is unverified, not known to be non-commercial; (b) OPUS-MT has no general en→ja model, so making it the default would turn every en→ja request without `engine` into a `DEPENDENCY_ERROR`; and (c) a different default would silently change the output of existing callers (video-production-agent included). Instead the unverified licence is made visible: `doctor --json` reports `weights_licence` for every engine (Argos: "unverified ..."), and the README and SKILL.md tell commercial work to choose **`engine: "opus-mt"` for ja→en** (or `ollama` with an Apache-2.0 model). DeepL stays optional, as before.
12. **Contract.** `opus-mt` and `ollama` are added to `operations.translate.engines` and `capabilities.translation_engines`, and the `translate` description changes. Both keys are in what video-production-agent pins, so the agent has to re-pin from the release that contains this. `parameters` and `contract_version` do not change: no request field was added (the engines are configured from the environment).
13. **Tests.** CI never downloads, converts or runs a model: `ctranslate2`/`sentencepiece` are replaced by fake modules over an empty model directory, and Ollama by a fake HTTP function (which fails the test if `/api/pull` is ever called).
